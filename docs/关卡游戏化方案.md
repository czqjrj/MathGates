# 关卡游戏化改造方案

> 目标：把「关卡」从「探索 + 答题 + 三星」升级为有**节奏、张力与成长反馈**的游戏体验。
> 本文件为设计稿 + 交付记录；P1 → P2 → P3 已全部落地（状态见 §8 里程碑、§9 决策记录）。
> 后续待办统一收敛到仓库根目录唯一的 `TODO.md`，本文件只保留设计与 schema 参考。

---

## 0. 结论先行

**能做，而且底子很好。** 项目已经有一套完整的元游戏系统（星级/经验/金币/勋章/称号/每日任务/商店/萌宠/错题本/连击），
真正缺的不是「从零做游戏化」，而是**把已经写好但没接上的东西用起来**，以及在**关卡内**补上节奏与张力。

三个最关键的现状发现：

1. **`Battle.gd`（755 行的对战 UI：六边形头像「推 vs 验」、能量条、连击 VFX、结算）是死代码。**
   它只在「关卡没有 `scene` 字段」时作为回退占位（`GameData.gd:486/1201/1344/1360`），
   而当前**所有关卡都带 `scene`**，所以它从不出现。
2. **5 个 BOSS 关现在就是普通 `LabStage` / `Lab3DStage`**，没有任何 boss 专属机制（无血条/无阶段/无演出）。
3. **关卡内的连击已有统计（`_streak`/`_max_streak`）**，但只有一个不显眼的小标签，没有可见的连击条/倍率。

|---|---|---|---|
| `LAB` | `LabStage.tscn` / `Lab3DStage.tscn` | 178 / 30 | 三阶段「实验探究→建构知识→迁移应用」（滑块/拖动/3D 实时重绘 + 追问） |

### 1.3 结算/奖励管线（`scripts/screens/StageBase.gd::_finish` ≈ line 583）

```
clean = 三阶段无失误轮数；ratio = clean/total
st = 3 if ratio>=0.8 else 2 if ratio>=0.6 else 0
if _trap_missed and st>0: st -= 1                      # 踩陷阱降星
GameData.grant_stars(lid, st)
GameData.record_level_result(lid, st, clean, total, _trap_missed)
reward = 30 + clean*15 + st*20 + (st>=3?60) + (no_trap?30) + _max_streak*3
if GameData.consume_coin_boost(): reward *= 2
GameData.add_coins(reward)
```

- 评级：`S`（满星+零失误+无陷阱）/`A`/`B`/`C`。
- 结算面板：`_victory`（标题/星级/评级/得分/金币 + 彩带/金币飞出）。
- 关卡进入：`GameData._enter_level()` 读 `level.scene`；无则回退 `Battle.tscn`。

### 1.4 「地图」真相

`scenes/WorldMap.tscn` **不是地理地图**，它就是 `scripts/modules/line/TheoremTree.gd` + `kind="method"`
（知识体系同理，`TheoremTree.tscn` = 同脚本 `kind="knowledge"`）。
所以「地图冒险化」= 扩展 `TheoremTree.gd` 的节点布局与装饰，而非新做地形。

## 3. P1 · BOSS 战真做

### 3.1 目标体验

BOSS 关 = 章节高潮：**守关者登场 → 你来我往（答对扣血 / 答错被反击）→ 击败演出 → 专属结算**。
保留原有三阶段探究（`lab_ref` 的探索/知识），在其上叠加战斗层——**不是**把 BOSS 降级成纯答题。

### 3.2 实现方式（推荐：作为 StageBase 的可选层）

> 备选方案（不推荐）：新建 `BossStage.tscn` 动态包裹 LabStage/Lab3DStage。因 2D/3D 两种基类不同，包裹会引入重复与分支，维护成本高。

**推荐做法**：把战斗层做进 `StageBase`，由配置开关，2D/3D 关卡自动共享。

1. **抽出可复用 HUD**：把 `Battle.gd` 的 `class HexAvatar` / `class HpBar` 移到新文件
   `scripts/ui/BossHud.gd`（纯绘制，无业务），`Battle.gd` 改为引用它（或随 Battle 一起保留）。
2. **StageBase 增加 Boss 层**（默认关闭）：
   - 判定：`_cfg.get("boss", {})` 非空 **或** `_level.archetype == "BOSS"` → `_boss_mode = true`。
   - 开启时在 `_ui` 顶部加一条战斗 HUD：`BossHud`（玩家血条 ↔ 守关者血条 ↔ 连击），
     血量与题量挂钩：`boss_max_hp = 题量`，`player_max_hp = 题量 + 容错`。
   - 作答回调里（`StageBase` 结算每题处）：
     - 答对 → 守关者掉血 + `Vfx.burst`；
     - 答错 → 玩家掉血 + `Vfx.ring`/`Vfx.shake` + 守关者"反击"飘字；
     - 更新 `_streak` 到连击条。
   - 阶段：守关者血量 ≤50% 进入**狂暴**（题干乱序或限时缩短或选项抖动，见 3.3 配置）。
   - 玩家血量归零 → 提前失败结算（`st=0`），保留 `record_level_result` 记账。
3. **结算**：击败时复用 `_finish` 的星级/金币管线，追加：
   - 击败演出（`Vfx.celebrate` + 弹窗"守关者已击败"）；
   - 首通奖励（见 3.4）。

### 3.3 数据 schema（`data/*_levels.json` 的关卡级新增，均可选）

```jsonc
"line_boss": {
  "name": "隐藏Boss · 对称与最值压轴",
  "stages": [ /* 原有三阶段 */ ],
  "boss": {
    "title": "对称最值·试炼",
    "avatar": "验",                    // 六边形头像字符
    "color": "#ff5e7a",
    "player_hp_bonus": 1,             // 玩家额外容错题数
    "enrage_at": 0.5,                 // 血量过半触发狂暴
    "enrage": { "shuffle": true, "shake": true },
    "reward": { "first_clear_coins": 200, "medal": "boss_line" }
  }
}
```

> 向后兼容：无 `boss` 块时行为与现在完全一致。

### 3.4 课程与存档改动

- `data/curriculum.json`：5 个 BOSS 关的 `scene` **保持不变**（仍走 LabStage/Lab3DStage，StageBase 自动识别 `archetype==BOSS`）。
  若希望显式，可加 `"boss": true`。
- `GameData.MEDALS`：追加「Boss 勋章」（如按击败数 `_boss_cleared_count()`，该函数已存在）。
- 奖励：首通 boots 金币 + 专属勋章；重复挑战仅常规奖励（避免刷币）。

### 3.5 涉及文件

- 新：`scripts/ui/BossHud.gd`
- 改：`scripts/screens/StageBase.gd`（Boss 层）、`scripts/screens/Battle.gd`（改用 BossHud）、
  `data/*_levels.json`（`boss` 块）、`data/curriculum.json`（可选）、`scripts/autoload/GameData.gd`（勋章）
- 测试：`tests/LabSmoke.gd` 加 boss 关、`tests/Tests.gd` 校验 `boss` 块结构与 id

### 3.6 风险

- StageBase 是所有 LAB 关的基类，改动需**严格默认关闭**，回归全套（Tests/LabSmoke/smoke_scene）必须全绿。
- 3D Boss（`space_boss`）血条层级要避开 3D 视口交互（放 HUD CanvasLayer，参照 `UiConst.LAYER_STAGE_HUD`）。

## 4. P2 · 关卡节奏强化（普惠所有关卡）

### 4.1 内容

1. **可见连击条 + 倍率**
   - 现在：`_combo_lbl`（`StageBase.gd:784`）只在连击时显示"连击 xN"。
   - 改为：顶部/侧边**连击进度条**，连击越高条越亮；连击 ≥3 时金币倍率 `1 + 0.1*(streak-2)`（上限如 ×1.5），
     结算面板显示"连击奖励 +N"。
2. **限时 / 速度奖励（可选）**
   - 关卡配置 `"time_limit": 秒`；超时不判负，只影响星级（或给"急速通关"额外金币）。
   - 结算显示用时与最快纪录。
3. **三星条件显式化 + 引导**
   - 结算面板增加"下一星差在哪"（如"再 1 轮无失误即可升 2 星"/"不用提示可拿 S"）。
   - 明确三星 = 零失误 & 未踩陷阱（现状）+ 可选限时。
4. **道具即时演出**
   - 用提示卡 / 双倍金币卡时给即时动画反馈（`Vfx` 已具备）。

### 4.2 数据 schema

```jsonc
// 关卡级或 stages 级
"rules": {
  "time_limit": 90,          // 秒，可选
  "star_time": 60,           // 三星时限，可选
  "show_combo_bar": true
}
```

### 4.3 涉及文件

- 改：`scripts/screens/StageBase.gd`（连击条/倍率/限时/结算文案）、
  `data/*_levels.json`（`rules` 块）、`scripts/autoload/GameData.gd`（可选 `best_time` 记录）
- 存档：`level_records{}` 增 `best_time`（旧存档缺字段按 0 处理，天然兼容）

### 4.4 风险

- 限时可能增加紧张感也可能增加挫败；建议**默认关闭**，按章节/题目类型逐关开启，并在设置里提供"计时开关"。

## 5. P3 · 地图冒险化

### 5.1 内容（作用于 `TheoremTree.gd`）

1. **分支路线**：章节/单元之间除了线性解锁，增加可选支线（同一章的不同方法路径）。
2. **宝箱节点**：达成条件（满星/连击/无错）掉落金币/道具/头像碎片。
3. **随机事件节点**：进入时触发小事件（限时挑战 / 双倍 / 迷你题）。
4. **章节 Boss 门**：章节内累计星数达阈值 → 获得"钥匙" → 解锁 `*_boss`。
   现有 `is_level_unlocked` 是线性判定，可扩展为"星数门槛或线性"。
5. **装饰与动效**：路径流光、节点呼吸、解锁礼花（`Vfx` 已有）。

### 5.2 数据 schema（实现：**关卡级**，向后兼容）

> **实现选型变更**：设计初稿用章节级 `map{ layout/nodes/edges/boss_gate }`。
> 落地时发现部分教材（如「圆锥曲线与方程」）会把多章合并成一张卡片，
> **章节级数据在合并下无法定位**；而关卡条目会随 `duplicate(true)` 合并原样保留。
> 因此改为在**每个 `level` 条目**上挂可选字段（缺省即旧行为）：

```jsonc
// data/curriculum.json 每个 level 条目内（全部可选）
"gate":   { "need_stars": 15 },                              // 章节 Boss 门：本单元累计星数门槛
"chest":  { "need_stars": 9, "title": "斜率补给箱",
            "reward": { "coins": 120 } },                     // 宝箱：达标可领，仅一次
"event":  { "title": "限时金币加成",
            "reward": { "coin_boost": 1 } },                   // 随机事件：面板首开触发一次
"optional": true, "after": "line_6_2"                         // 支线：抽离主路径，弧线连回 after 关
```

> `reward{}` 复用 `GameData.grant_reward()`，支持 `coins` / `hint_tokens` / `coin_boost`。
> 缺省时：`_level_unlocked` 仍是线性判定；无 `chest/event` 的关节点不画额外角标；无 `optional` 则维持原蛇形路径。

### 5.3 涉及文件

- 改：`scripts/modules/line/TheoremTree.gd`（布局/节点类型/面板/解锁/庆祝）、
  `scripts/autoload/GameData.gd`（`stars_of`/`claim_chest`/`is_chest_claimed`/`is_event_seen`/`mark_event_seen`/`grant_reward`）、
  `data/curriculum.json`、`tests/Tests.gd`（`_test_adventure`）
- 存档：新增 `chests_claimed{}`、`events_seen{}`（`_blank_user`/`_snapshot`/`_apply` 三处同步）

### 5.4 交付状态与实现说明

- **已交付**（`Tests: 1220 passed`、`smoke 238 ok`、`LabSmoke TMP_OK`、运行期探针 `24 passed`）。
- 分支路线：`optional:true` 的关卡从主蛇形路径抽离，排到末尾「支线探索」行，并用二次贝塞尔弧连回 `after` 节点。
- 事件节点：**进入面板首开即触发**（非独立小游戏/迷你题），发放即时奖励；重复打开不再发奖。
- 宝箱奖励：当前为 `coins` / `hint_tokens` / `coin_boost`；**头像碎片、满星/连击条件尚未实现**（`need_stars` 是唯一条件）。
- 装饰动效：可领取宝箱脉冲、事件菱形呼吸环、支线标签、解锁礼花（仅进度刷新时对本次新解锁节点放一次）。
- **风险**：`TheoremTree.gd` 同时被「知识体系」和「方法推演」复用，两者走同一 `_build_map` 路径，
  已确认不分 `kind`，两种 `kind` 均已回归。
