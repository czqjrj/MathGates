# B11 · 质量验收标准体系（v1.0）

## 一、核心验收维度（3+4 结构）

### 第一层面：内容完整性（您提出的 3 项 + 补充 1 项）

| 维度 | 验收标准 | 权重 | 达标线 | 检测方法 |
|-----|---------|-----|-------|---------|
| **A. 知识点覆盖** | 该章节所有重要知识点是否都有对应的讲解题？ | 25% | ≥90% | 对照课标/教材目录逐项核对 |
| **B. 题型方法覆盖** | 该章节典型解题方法是否有至少 1 道例题？ | 25% | ≥85% | 列出方法清单→逐一验证 |
| **C. 交互动画覆盖** | 每个核心知识点是否有交互探索环节？ | 20% | ≥80% | 检查 explore 题占比≥30% |
| **D. 难度梯度合理性** | 从易到难是否有合理的难度递进？ | 15% | ✓ 人工审核 | 题目按难度排序后目测连续性 |

### 第二层面：学习体验（新增 4 项）

| 维度 | 验收标准 | 权重 | 达标线 | 检测方法 |
|-----|---------|-----|-------|---------|
| **E. 概念理解友好度** | 学生能否通过互动快速建立直观认识？ | 10% | ✓ 用户测试 | 邀请 3-5 名试学，观察是否"一看就懂" |
| **F. 迁移应用能力** | 学完本章是否能独立解决新题？ | 5% | ✓ 迁移测试 | 提供章末综合题，正确率≥70% |
| **G. 认知负荷控制** | 单道题信息量是否适中？有无过载？ | - | ✓ 专家评审 | 每道题≤3 个新概念同时出现 |
| **H. 错误诊断支持** | 答错时能否获得针对性反馈？ | - | ✓ 功能检查 | 随机选 10 题测试 explain 的针对性 |

## 二、量化指标矩阵（章节级）

### 必须达标的硬性指标

| 指标名称 | 计算公式 | 最低要求 | 目标值 | 优秀值 |
|---------|---------|---------|-------|-------|
| **知识点覆盖率** | (已覆盖知识点数 / 总知识点数)×100% | 90% | 95% | 100% |
| **方法覆盖率** | (有例题的方法数 / 总方法数)×100% | 85% | 95% | 100% |
| **交互题占比** | (explore 题数 / 总题数)×100% | 30% | 40% | 50% |
| **高交互题数量** | 具备≥2 个滑块 + 实时读数的 explore 题数 | ≥2 道/章 | ≥3 道/章 | ≥5 道/章 |
| **平均深度分** | analyze_depth_v3.py 输出的 depth_score | ≥0.45 | ≥0.50 | ≥0.55 |
| **explain 完整率** | 有 explain 的题目数 / 总题数 | ≥95% | 100% | 100% |
| **无填空题原则** | input 类型题占比 ≤ 30% | ≤30% | ≤20% | ≤10% |

### 加分项指标（可选优化）

| 指标名称 | 说明 | 加分条件 |
|---------|------|---------|
| **跨章关联提示** | 在 explain 中提及与其他章节的联系 | 每章≥3 处 |
| **生活应用场景** | 包含实际应用例题或讨论 | 每章≥1 道 |
| **历史背景介绍** | 融入数学史元素增强趣味性 | 每章≥1 处 |
| **可视化多样性** | 使用超过 2 种以上的图形展示方式 | ✓ 存在 |

## 三、验收流程（每章执行）

### 阶段 1：自动检测（5 分钟）

```bash
# 1. 运行深度分析
python tools/analyze_depth_v3.py > output.txt

# 2. 提取关键指标
grep "depth_score\|interaction_quality\|method_coverage" output.txt

# 3. 检查是否有异常数据
python tools/check_question_quality.py <chapter_file>
```

**通过条件**：
- ✅ depth_score ≥ 0.45
- ✅ interaction_quality ≥ 0.20
- ✅ method_coverage ≥ 0.60
- ✅ input 占比 ≤ 30%

### 阶段 2：人工核查（30 分钟）

#### A. 知识点覆盖核查表

以**集合逻辑**为例：

| 序号 | 知识点 | 是否有题 | 题号 | 备注 |
|-----|--------|---------|------|------|
| 1 | 集合的概念与表示 | ✅ | set_concept_1 | - |
| 2 | 子集与真子集 | ✅ | set_subset_1 | - |
| 3 | 集合相等判定 | ⚠️ | - | **需补充** |
| 4 | 并集运算 | ✅ | set_union_1 | - |
| 5 | 交集运算 | ✅ | set_intersect_1 | - |
| 6 | 补集运算 | ✅ | set_complement_1 | - |
| 7 | 容斥原理 | ✅ | set_venn_interactive_1 | 新增 |
| 8 | 韦恩图应用 | ⚠️ | - | **需补充** |

**覆盖率**: 6/8 = 75% → **不达标**（需≥90%）

#### B. 方法覆盖核查表

| 方法名称 | 对应题号 | 题型 | 是否有交互 |
|---------|---------|------|-----------|
| 列举法表示集合 | set_concept_1 | choice | ❌ |
| 描述法表示集合 | set_concept_2 | pick | ❌ |
| 判断子集关系 | set_subset_1 | pick | ❌ |
| 韦恩图分析 | set_venn_interactive_1 | **explore** | ✅ |
| 容斥原理计算 | set_complement_1 | pick | ❌ |

**方法覆盖结论**: 需要补充交互题型比例

### 阶段 3：用户体验测试（30 分钟）

#### C. 学生试学观察记录表

邀请 3 名不同水平的学生试学本章，记录：

| 学生编号 | 背景 | 完成时间 | 困惑点 | 理解评分(1-5) |
|---------|------|---------|--------|--------------|
| S1 | 基础薄弱 | 25min | 容斥原理公式推导 | 3 |
| S2 | 中等水平 | 18min | 无明显困惑 | 4 |
| S3 | 学有余力 | 15min | 希望有更多挑战题 | 5 |

**平均分**: (3+4+5)/3 = 4.0 → **达标**（≥3.5）

#### D. 交互流畅性检查

逐项检查每道 explore 题：

| 题号 | 滑块数量 | 实时读数 | 反馈及时性 | 综合评价 |
|-----|---------|---------|-----------|---------|
| set_venn_interactive_1 | 3 ✓ | 4 ✓ | <0.5s ✓ | 优秀 |
| set_op_properties_explore_1 | 4 ✓ | 3 △ | <1s △ | 良好 |

**结论**: 基本满足交互友好要求

### 阶段 4：决策会议（15 分钟）

根据上述检查结果，做出最终验收决策：

| 决策选项 | 条件 | 下一步行动 |
|---------|------|-----------|
| ✅ **直接通过** | 全部指标达标，无重大缺陷 | 合并代码，标记章节完成 |
| 🔶 **有条件通过** | 主要指标达标，少数次要点待改进 | 创建 Issue，限期 3 天修复 |
| ❌ **不通过** | 核心指标未达标或缺少关键知识点 | 退回重新补强 |

## 五、实施建议

### 优先级策略

| 阶段 | 重点维度 | 可暂不考核维度 |
|-----|---------|--------------|
| Phase 1（当前）| A/B/C/E（内容 + 交互） | F/G/H（高阶体验） |
| Phase 2 | 加入 F（迁移能力） | G/H |
| Phase 3 | 全面考核所有维度 | 无 |

### 工具支持

建议开发的辅助脚本：
1. `check_knowledge_coverage.py` - 自动识别知识点覆盖缺口
2. `check_method_examples.py` - 检测方法实例是否齐全
3. `check_interaction_quality.py` - 评估交互设计友好度
4. `generate_checklist.py` - 自动生成章节验收清单
